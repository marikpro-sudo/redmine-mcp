# Установка для разработчика

Нужны доступ к приватному репозиторию, Git, Node.js версии 22.16 или новее
и личная учётная запись Redmine с доступом к нужным проектам. На Windows для
скрипта настройки нужен PowerShell 7 (`pwsh`).

## 1. Получить код

Примите приглашение владельца в GitHub, затем клонируйте приватный репозиторий:

```powershell
git clone git@github.com:marikpro-sudo/redmine-mcp.git
cd redmine-mcp
npm.cmd ci --ignore-scripts
npm.cmd test
```

Для SSH требуется ключ, добавленный в ваш GitHub-аккаунт. Можно использовать
HTTPS-адрес клонирования с авторизацией через установленный Git Credential Manager.
Не включайте токен GitHub в URL или файлы проекта.
На Linux/macOS используйте `npm` вместо `npm.cmd`.

## 2. Настроить личный доступ

Уточните у владельца адрес Redmine и идентификатор проекта. Администратор Redmine
должен включить REST API. Получите свой API-ключ в настройках своей учётной записи.
Доступ к GitHub и доступ к задачам Redmine предоставляются отдельно.

На Windows выполните, подставив реальные адрес и проект:

```powershell
pwsh -File ./scripts/configure.ps1 -RedmineUrl https://redmine.example.com -Project your-project
```

Ключ вводится скрыто. Скрипт создаёт `.env` с доступом только вашей учётной записи
Windows; существующий файл не перезаписывается. Параметр `-Project` можно опустить:
тогда список охватит все видимые проекты. Часовой пояс задаётся через `-TimeZone`,
по умолчанию `Asia/Almaty`.

На Linux/macOS:

```sh
(umask 077; set -C; cat .env.example > .env)
chmod 600 .env
```

Команда создания не перезаписывает существующий `.env`. Откройте его в редакторе,
замените пример адреса и ключа, укажите проект и часовой пояс.
Для MCP достаточно настроек Redmine; `REDMINE_ACCESS_TOKEN` нужен только для
необязательного локального HTTP API.

Проверьте подключение из папки репозитория:

```sh
node --env-file=.env src/cli.js me
node --env-file=.env src/cli.js list
```

Убедитесь, что `me` показывает вашу учётную запись. Не используйте общий ключ администратора.

## 3. Подключить MCP

Возьмите шаблон [examples/mcp.json](examples/mcp.json) и замените оба пути на
абсолютные пути к своему клону. Например, для `C:/Projects/redmine-mcp`:

```json
{
  "mcpServers": {
    "redmine": {
      "command": "node",
      "args": [
        "--env-file=C:/Projects/redmine-mcp/.env",
        "C:/Projects/redmine-mcp/src/mcp.js"
      ]
    }
  }
}
```

Это пример для клиентов с секцией `mcpServers`. Если клиент предлагает отдельные
поля Command и Arguments, перенесите те же значения. На Linux/macOS пути могут
выглядеть как `/home/user/projects/redmine-mcp/src/mcp.js`.
Если клиент не находит `node`, укажите абсолютный путь к исполняемому файлу Node.js.

Перезапустите MCP-клиент. Проверьте инструмент `redmine_me`, затем запросите свои задачи.
Правила подготовки комментариев описаны в [COMMUNICATION.md](COMMUNICATION.md),
все инструменты и ограничения — в [README.md](README.md).

## Обновление

Остановите MCP-процесс или закройте клиент, затем в папке репозитория выполните:

```powershell
git pull --ff-only
npm.cmd ci --ignore-scripts
npm.cmd test
```

Перезапустите клиент. Личный `.env` не хранится в Git и остаётся на компьютере.
Не пересылайте `.env`, API-ключи и журнал операций другим разработчикам.

## Создание задач с выбором статуса в версии 0.4

После обновления перезапустите MCP-процесс. Для создания задач всех пяти типов SAP администратор
сначала обновляет серверный модуль `redmine_completed_work` до версии 1.1.0 и проверяет начальные статусы разработчика и руководителя.
Чтение и изменение существующих задач продолжают работать без него.
Проверка подключения новой функции: `node --env-file=.env src/cli.js creation-context`.
Полный порядок, обязательные поля и ограничения: [COMPLETED-WORK.md](COMPLETED-WORK.md).
